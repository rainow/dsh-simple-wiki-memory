# reference/skills/ — 技能记忆

这里存 **skill / MCP 使用中的稳定外部事实与坑点**（ID、枚举值、端点、配额、"必须先做 X"这类）。
完整规则见 `~/.dsh/AGENTS.md`：规则 2（定归属两问 + 准入四道闸 + 记录规范 + 晋升 lint）· 规则 6（检索）· 规则 7（出错即回报）。

## 归属怎么判

1. 有**该工具专有的标识符**（API 参数名、`code` / `id`、端点、错误码、枚举值）→ 放这里
2. 没有，且**换个工具也成立**（口味、住址、称呼、忌口）→ 放 `reference/<主题>.md`
3. 两类都有 → 主体放这里；跨工具的偏好另存 `reference/`，**并在这里加一行指针**
4. 犹豫超过一秒 → 问用户，不要猜
5. 拟定的文件名里含工具名（`mcd`、`blender`）→ 说明它本来就该在这里

## 命名

- skill：`<skill-id>.md`（小写；`/` → `__`）
- MCP：`mcp-<server-name>.md`
- 以 `_` 开头的文件是说明文档，不是技能记忆

## 模板

```markdown
---
skill: <skill-id>          # 或 mcp: <server-name>
verified_at: YYYY-MM-DD    # 最近一次确认准确的日期
---

## 速查

| 用途 | 值 |
|---|---|

## 必传参数 / 特调

## 坑

- 现象 → 结论
```

## 硬规矩

1. **不写流程** —— 流程属于 SKILL.md，会随 skill 更新
2. **不写密钥** —— 密码 / token / API key / 私钥、与用途无关的个人安全细节
3. **冲突不覆盖** —— 新旧矛盾时标 ⚠️、两条都留，让用户判断
4. **删除测试** —— 每行问「删掉它，下次会出错吗？」不会就删
5. **三类禁写** —— 工具 schema 已声明的 / 能现场查到的（价格、地址全称、余额）/ 会变的
6. **预算** —— 单文件 ≤ 6KB / 80 行；超了先压缩，压不下去再向用户申请超限
7. **不写变更记录** —— 用 frontmatter `verified_at`；只留结构性变更一行
8. **与 SKILL.md 去重** —— SKILL.md 已有的不重复存；发现重复以 SKILL.md 为准删除

## 出错怎么办

用起来发现记忆与实际不符 → **先标 `❓待核实（日期）`，不要静默改数** → 写 pending 说明
「原记录 / 实际 / 证据」→ 当场告诉用户 → 确认后再改并更新 `verified_at`。
